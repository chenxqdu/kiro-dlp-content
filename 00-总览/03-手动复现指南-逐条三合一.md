# 手动复现指南：DLP L0–L4 全用例 · 逐条三合一（输入 → 效果 → 延迟）

> 面向想**亲手把每一条用例跑一遍、并同时看到「输入原文 + 效果（裁决/脱敏） + 延迟」**的人。
> 两方案（方案一 LiteLLM 网关 / 方案二 selective-bump MITM）**共享同一个 DLP 引擎**（`engine/dlp/`），
> 所以引擎层的用例复现只写一次，两方案各写一节集成层复现。

---

## 0. 总览与心智模型

### 0.1 一张图：共享引擎 + 两方案集成层

```
              ┌───────────────────────── 两方案共享 ─────────────────────────┐
   输入文本 →  │  L0 正则/词表 → L1 detect-secrets → L2 熵+上下文             │
              │  → L3 Presidio(PII/NER) → L3.5 术语表/EDM(Aho-Corasick)      │  → 裁决 verdict
              │  → L4 语义(异步·仅告警,不改裁决)                              │    (pass/redact/block)
              └──────────────────────────────────────────────────────────────┘
                        ▲ from dlp.engine import DLPEngine ▲
          ┌─────────────┴─────────────┐        ┌───────────┴──────────────────┐
   方案一：LiteLLM 网关(改 base_url)          方案二：selective-bump MITM(不改 base_url)
   客户端 → :4000 /chat/completions           客户端 →(TLS 劫持 runtime.us-east-1.kiro.dev)
   → CorpDLPGuardrail.scan() → 放行/改写/400   → mitm addon → DLP /inspect(:9000).scan() → 放行/改写/短路
```

**关键含义**：
- L0–L4 的**检测正确性**由共享引擎决定 → **56 场景集 + 78 分层集**这两套 fixture 与「用哪个方案」无关，
  本机 `python3` 离线跑一遍，即同时验证了两方案的检测内核。
- 两方案只在**集成层**不同：方案一在网关进程内 `import` 引擎；方案二在独立 `/inspect` 薄服务里 `import` 同一引擎。

### 0.2 为什么需要「三合一」这个新视图

现成的 runner 各自只给一部分，且**输入原文只躺在 fixture JSON 里**：

| 工具 | 有 | 缺 |
|---|---|---|
| `run_offline.py`（56 场景） | ID·期望·实际 verdict·top_layer·**总 ms**·命中规则 | 输入原文、脱敏后文本、**分层延迟** |
| `run_layers.py`（78 分层） | ID·层·✓/✗·**该层 ms**·说明 | verdict 值、输入原文、脱敏输出 |
| 方案二 `/inspect` 返回 JSON | verdict·top_layer·rules·**分层 latency_ms + http_total**·redacted_body | 只经 `json.tool` 打屏，**不按 fixture 逐条跑、不归档** |

`inspect_cases.py` 把三者按**用例 ID** join 成逐条卡片：从 fixture 取输入原文，配一次裁决的效果 + 分层延迟。

### 0.3 两条复现路径 × 两方案集成层（一句话对比）

| | 路径 A：本机离线快跑 | 路径 B：完整实例复现 |
|---|---|---|
| 环境 | 本地 `python3`，零成本 | 启 EC2（`KIRO_DLP_INSTANCE`），有成本 |
| L3-Presidio | 不可达 → 自动 SKIP（`requires:presidio`） | 真 NER 参与 |
| L4-Bedrock | 默认关；`--bedrock` 才跑（⚠ 数据出 VPC，仅功能验证） | 同 |
| 延迟意义 | 单次冷跑，**含 L3 连接超时**，仅「示意」 | 真链路 RTT，但仍单发、非分位 |
| 覆盖 | 共享引擎检测内核（= 两方案内核） | + 各方案集成层（网关 HTTP / MITM 真链路） |

> **基准延迟分位数**（p50/p95/p99）一律**以 k6 压测为准**，不看本指南任何单发 ms：
> 方案一 → [`方案一-litellm-gateway/testing/results-2026-08-10/perf/`](../方案一-litellm-gateway/testing/results-2026-08-10/perf/)（03 §9）；
> 方案二 → [`方案二-03-测试报告.md`](../方案二-selective-bump-mitm/方案二-03-测试报告.md) 压测节。

## 1. 共享引擎离线复现（方案无关，本机 Python3）

> 目录基准：`cd engine`。无需装 Presidio/Bedrock；L3、L4-Bedrock 向量会自动标 SKIP（不算 fail）。

### 1.1 全量整机裁决（56 场景集）

```bash
cd engine && python3 -m tests.run_offline --no-color
```

判读硬门：套件1（金标准）**漏拦=0**、套件2（合法基线）**误报=0**、合计 **56/56 pass**。
（此处 L3-only 用例走「L3 缺席豁免」——见 [1.5](#15-l3-缺席与-skip-语义不伪造)。）

### 1.2 全量分层（78 分层集）

```bash
python3 -m tests.run_layers --no-color
```

离线判读：**65/78 pass + 13 skip**（skip = L3×9 + L4-bedrock×4）。带 `--bedrock` 会再跑 4 条 L4 向量。

### 1.3 逐条三合一（本指南核心工具）

`inspect_cases.py` 是**只读**联接器——不改任何生产代码、不写 fixture，全靠 `import` 复用两个 runner 的判定件。

```bash
# 单条速查（三合一卡片：输入原文 + 期望vs实际 + 分层延迟）
python3 -m tests.inspect_cases --id S1-01 --set offline

# 按套件 / 按层过滤
python3 -m tests.inspect_cases --suite 1 --set offline
python3 -m tests.inspect_cases --layer L0 --set layers

# 全量 + 生成可浏览报告（markdown 表格 + jsonl 原始记录）
python3 -m tests.inspect_cases --set both --format md --report results-manual/manual_YYYYMMDD
```

一张卡片长这样（S1-09，redact）：

```
[S1-09] ✓  期望=redact/L0  实际=redact/L0  «local»
  输入: 用户身份证 110101199003070011,请登记。
  命中: cn_id_card·CN_ID_CARD·redact·raw
  脱敏后: 用户身份证 [REDACTED:CN_ID_CARD],请登记。
  延迟(ms): L0=0.0 L1=0.0 L2=0.0 L3=8.7 L3.5=0.0 total=8.9   [示意·本地单次冷跑（离线 L3 计入 Presidio 连接超时）]
```

**卡片字段逐一**：`ID` | `集/层/套件` | `来源(local / via-http)` | `SKIP 原因(若跳过)` | `输入原文` |
`期望 vs 实际`（56 集=verdict/top_layer；78 集=命中集 vs must_hit） | `✓/✗/~` |
`命中明细(rule·entity·action·source，**无 matched/span**)` | `脱敏后文本(仅 redact)` |
`forced_block(仅 via-http fail-closed 触发)` | `分层延迟 ms + total(标"示意·单次")` | `L4 告警` | `notes`。

**CLI 速查**：

| 分组 | 参数 | 说明 |
|---|---|---|
| 过滤 | `--id A,B` / `--layer L0..L4\|EGRESS\|NORM` / `--suite 1-6` / `--set offline\|layers\|both` / `--all` | 可组合 |
| 来源 | *(默认本地)* / `--via-http <url>` | via-http 见 [4.1](#41-服务级逐条三合一via-http本节核心) |
| 输出 | `--format terminal\|md\|jsonl` / `--report <前缀>` / `--full-text` / `--no-color` | 报告写 `<前缀>.md` + `<前缀>.jsonl` |
| 其他 | `--bedrock` | 本地跑 `requires=bedrock` 的 L4（⚠ 数据出 VPC，仅功能验证） |

### 1.4 按层手动复现 L0–L4（78 分层集）

每层 `python3 -m tests.inspect_cases --layer <层> --set layers`。各层测什么、fixture 文件、典型形态：

| 层 | fixture | 测什么 | 输入字段 | 效果字段 | 典型三态 |
|---|---|---|---|---|---|
| **L0** 正则/词表 | `fixtures_layers/l0.json` | AWS key / 卡号(Luhn) / 身份证 / 内部域名 | `text` | `must_hit{rule,entity,action}` | 正例命中 · 豁免零命中 · 边界(校验位) |
| **L1** detect-secrets | `l1.json` | 私钥 / token / 高熵密钥（工具级） | `text` | 同上 | 正例 · 测试占位豁免 |
| **L2** 熵+上下文 | `l2.json` | 无明确规则的高熵串 + 上下文词触发 | `text` | 同上 | 熵达阈 · 低熵豁免 |
| **L3** Presidio | `l3.json`（`requires:presidio`） | PII/NER（人名/邮箱/电话/IP，中英双语） | `text` | 同上 | **本地必 SKIP**，实例上跑 |
| **L3.5** 术语表/EDM | `l35.json` | 企业专有词 / EDM 精确数据匹配（Aho-Corasick） | `text` | 同上 | 术语命中 · 相似词豁免 |
| **EGRESS** 外发通道 | `egress.json` | 工具调用外泄（cat\|curl / --data / git push / 非白名单域） | `tool`+`args` | `must_hit` / `exact_none` | 外泄 BLOCK · 白名单零命中 |
| **NORM** 预处理 | `norm.json` | 变体归一（NFKC/去零宽/中文数字/剥分隔符/折叠拼接） | `text`+`func` | `expect_contains`（无 verdict） | 变体还原出目标串 |
| **L4** 语义 | `l4.json` | 专有业务逻辑/源码语义告警（**异步·不改裁决**） | `text`+`use_bedrock` | `expect_alert`（类别或 null） | 启发式告警 · `--bedrock` 真语义 |

> **NORM / L4 不产生整机 verdict**：卡片用「变体/告警」列渲染，不显示 pass/redact/block。
> **EGRESS** 输入是 `{tool,args}` JSON，卡片按 JSON 渲染，命中为 `egress_channel` 通道规则。

### 1.5 L3 缺席与 SKIP 语义（不伪造）

- 本地无 Presidio → `requires:presidio` 向量（L3 集 9 条）**SKIP**；56 集里 top_layer==L3 且 notes 含 "L3 skipped" 且 verdict==pass 的用例，按引擎 §9 记 **L3 缺席豁免**（既不判 pass 也不计漏拦）。
- `requires:bedrock` 且未给 `--bedrock` → **SKIP**（L4 集 4 条）。
- **SKIP 一律不算 fail**。卡片会写明 SKIP 原因，绝不用占位数字冒充结果。

## 2. 延迟口径（统一小节，务必读）

三种 ms 出处不同、含义不同，**绝不能混用**：

| 来源 | 卡片标注 | 含义 | 能不能当基准 |
|---|---|---|---|
| 本地 `inspect_cases`（默认） | `示意·本地单次冷跑` | 单发；**离线时 L3 计入 Presidio 连接超时**（如 S1-01 L3≈200–400ms 纯超时，非 NER） | ❌ 仅示意 |
| `inspect_cases --via-http` | `示意·远程单发` | 方案二真引擎单次处理耗时（Presidio 可达时是真 NER），含 server 追加的 `http_total` | ❌ 仍单发 |
| k6 压测 | —（不在卡片里） | 开环 `constant-arrival-rate`，p50/p95/p99 分位 | ✅ **唯一基准** |

基准出处：方案一 [`results-2026-08-10/perf/`](../方案一-litellm-gateway/testing/results-2026-08-10/perf/)（03 §9，拐点 ≈80 req/s）；方案二 03 测试报告压测节。

## 3. 方案一集成层复现（LiteLLM 网关）

### 3.1 内核已被本机覆盖

网关的 `CorpDLPGuardrail` 直接 `import` 共享引擎，故 [第 1 节](#1-共享引擎离线复现方案无关本机-python3)的 `run_offline` / `run_layers` / `inspect_cases` 已把检测内核验完。网关**端到端**另需下面两步。

### 3.2 完整实例复现（真 NER + 网关 HTTP RTT）

远程脚本经 SSM 投递到实例执行（本机发起，实例上跑）：

```bash
cd 方案一-litellm-gateway/testing/remote
./ssm_exec.sh host_stage1_offline.sh          # 阶段1：离线 56 条
./ssm_exec.sh host_stage2_gateway.sh 900      # 阶段2：网关集成(test_gateway.py 46 例，block→400/其余→200)
./ssm_exec.sh host_stage5_layers.sh           # 阶段5：分层 78 条(Presidio 全量 + L4 --bedrock)
```

在实例上（Presidio 可达）直接跑 `inspect_cases`，即可看到 **L3 真正参与**的分层延迟：

```bash
# 实例 kiro-dlp 上，engine/ 目录内
python3 -m tests.inspect_cases --layer L3 --set layers          # 此时不再 SKIP
python3 -m tests.inspect_cases --set both --format md --report results-manual/onhost_YYYYMMDD
```

### 3.3 逐条效果 + 延迟的取法

- 端到端**裁决对错**：`gateway/test_gateway.py`（fixture → `/chat/completions`，block→400 / redact·pass→200）+ 网关 metrics 计数。
- 但 **metrics 只有 count、无逐条输入/延迟**；要「输入→效果→延迟」逐条对齐，用 `inspect_cases`（在实例上跑，L3 真参与）。
- **基准分位**看 [`results-2026-08-10/perf/`](../方案一-litellm-gateway/testing/results-2026-08-10/perf/)，别拿 `inspect_cases` 的单发 ms。

## 4. 方案二集成层复现（selective-bump MITM）

方案二的引擎跑在独立 `/inspect` 薄服务里（私网 `172.31.27.174:9000`，另有 `GET /health`）。
`/inspect` 返回 JSON **自带分层 latency_ms + http_total + verdict + rules + redacted_body**——
`inspect_cases --via-http` 正是把这份 JSON 按 fixture 逐条 join 成三合一卡片，**补上 Tier D stdout 缺的逐条延迟**。

### 4.1 服务级逐条三合一（`--via-http`，本节核心）

同一套 56 用例，包 CodeWhisperer 信封 POST 到方案二真引擎服务：

```bash
# 在 DLP 主机上（或经 SSM 在能访问 172.31.27.174:9000 的节点），engine/ 目录内
python3 -m tests.inspect_cases --set offline \
  --via-http http://172.31.27.174:9000 \
  --format md --report results-manual/via_http_YYYYMMDD
```

行为：
- 先 `GET /health` **探活**——不可达则**整批标 SKIP(service-down)** 并提示「须在 DLP/proxy 主机经 SSM 跑」，**绝不伪造**。
- 可达则逐条 POST `{"conversationState":{"currentMessage":{"userInputMessage":{"content":<fixture.content>}}}}`，
  把返回 JSON 映射进卡片：`verdict` ↔ 期望、`rules` ↔ 命中明细（**契约已脱去 matched/span**）、
  `latency_ms`（含 `http_total`）、`redacted_body` ↔ 脱敏后文本、`forced_block` 单列高亮。
- **注入点差异**：`/inspect` 固定按 PROMPT 注入点判定；56 集里非 prompt 的用例（如套件4 mcp）差异属预期，
  卡片降级为 note/SKIP（不硬判 fail），并显式写明。
- **78 分层集不经 `/inspect`**（EGRESS/NORM/L4 非整机裁决）→ `--via-http` 下这些自动 SKIP(not-applicable-to-http)。

### 4.2 真链路分层复现（`run_all.sh`）

在**验证节点 proxy EC2** 上经 SSM 跑（`bash≥4`；`❌|FATAL`=FAIL）：

```bash
cd ~/tests && ./run_all.sh            # 全部：0 a b c d f
./run_all.sh --list                   # 列层
./run_all.sh 0 a                       # 只跑预检 + Tier A
```

| 层 | 脚本 | 验什么 |
|---|---|---|
| `0` | 内联 | §2 bump 域严格校验（Verify 0 + issuer=我方中间 CA）+ §3 透传域红线（issuer=Amazon，绝不为我方 CA） |
| `a` | `tier_a_smoke.sh` | §4 Tier A：`/inspect` 三态裁决 + 脱敏字段不外泄 |
| `b` | `tier_b_wire.sh` | §4 Tier B：wire-byte 铁证（发往上游字节：PASS 逐字节一致 / REDACT PII 消失 / BLOCK 上游零命中） |
| `c` | `tier_c_real_upstream.sh` | §4 Tier C：真实上游交叉核对（PASS 到 AWS / BLOCK 我方短路） |
| `d` | `tier_d_relayer_layers.sh` | §4.4 Tier D：真实链路按层拆开 L0–L3.5，双断言 verdict + top_layer |
| `f` | `tier_fail_modes.sh` | §5 fail 模式四子测（不可达吃策略 / HTTP503 恒 closed） |

> **oracle（应该怎样）** 见 [TEST-PLAN.md](../方案二-selective-bump-mitm/TEST-PLAN.md)；**实测（实际怎样）** 见 [方案二-03-测试报告.md](../方案二-selective-bump-mitm/方案二-03-测试报告.md)。
> **Tier D ≠ stage5 的 78 条**：stage5 是本机直调每层 `scan()`；Tier D 每条探针都**穿过真实 addon → HTTP → :9000** 再由 echo 上游做字节取证。两者互补，stage5 全绿不替 Tier D 背书。

### 4.3 fail-closed 手动坐实

停 Presidio 后，对 L3-only 向量（如公开 Luhn 合成卡号 `4539578763621486`）打 `/inspect`：
返回 `verdict=BLOCK` + `forced_block=l3_unavailable`——`--via-http` 卡片会**直接高亮 forced_block** 列。
含义：L3 不可达时 fail-closed（默认 `block`），敏感数据**不出网关**；对照旧 fail-open（`keep`，非生产）则明文外发。
量化见方案一 03 §9.12 的 keep 对照实验。

## 附：安全与边界

- fixture 内敏感值均为**合成/公开示例串**（AWS 文档 key、Luhn 合成卡号、mod-11 合成身份证），非真实凭证；且早已在已提交 JSON 里，回显进报告不引入新泄漏。
- 命中明细与 jsonl **不落 `matched`/`span`**（原始敏感子串），与方案二 `/inspect` 契约一致；REDACT 的脱敏后文本本就安全，照录。
- **实例成本**：路径 B 需启 `KIRO_DLP_INSTANCE`；跑完记得 stop / 还原。跨方案清理有已知坑（按 ancestor 误杀 `kiro-dlp-http`），复原须核对状态，见方案二真机踩坑实录。
