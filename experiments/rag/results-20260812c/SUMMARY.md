# 待测项 5 · 跨语言（非 C/C++）代码克隆真机实测摘要 · 2026-08-12c

> 环境：**g5.xlarge（NVIDIA A10G 24G，us-west-2）**（g6/L4 四 AZ 均无容量，退 A10G），
> torch 2.13.0+cu130 / transformers 5.15.0 / sentence-transformers 5.7.0 / scikit-learn 1.7.2。详见 `env.txt`。
> **所有数字取自机器输出，无手写。** 上轮 C/C++（POJ-104，L4 卡）数据在同级 `../results-20260812b/`。

**本轮回答一个问题**：上轮 POJ-104（C/C++）上「代码嵌入 F2LLM 碾压通用 bge-m3（AP 1.000 vs 0.748）」，
是 C/C++ 专属还是能泛化到 Python？

- **数据集**：Project CodeNet **Python800** 基准子集（IBM，NeurIPS 2021，arXiv:2105.12655，源码 Apache-2.0；
  官方明言可作 POJ-104 的替代/补充）。同题=Type-4 语义克隆，与 POJ-104 的 label 分组语义完全等价。
- **派生口径与 POJ 轮完全对齐**：10 题建库（每题 1 条=登记机密）/ 每题 3 条同题提交=改写正例 / 20 条异题=负例
  （`build_codenet_eval.py`，确定性派生可复现；原始 tarball 运行时下载不入 git）。
- **评测管线零改动**：`rag_service.py`（MODEL env 切换）+ `threshold_sweep.py`，与上两轮同一套。

## 结果：F2LLM 碾压 bge-m3 在 Python 上**成立且差距更狠**

| 指标（CodeNet Python800，10题·30正20负） | codefuse F2LLM-v2-4B（代码向） | BAAI/bge-m3（通用） | 原始文件 |
|---|---|---|---|
| **AP** | **1.0000**（ROC-AUC 1.0000） | 0.8999（ROC-AUC 0.8450） | `sweep_{f2llm,bge-m3}_codenet-py.json` |
| **top-1 检索准确率**（正例 top 命中==源题，防 AP 饱和锚） | **30/30 = 1.000**（Wilson 95% CI [0.887, 1.0]） | **19/30 = 0.633**（CI [0.455, 0.781]） | `retrieval_topk.json` |
| 正例相似度范围 | 0.473–0.943 | 0.716–0.922 |  |
| 负例相似度范围 | **0.107–0.361**（与正例完全分离） | **0.634–0.806**（与正例严重重叠） |  |
| 推荐工作点（recall≥1.0） | threshold=0.473，precision=1.000 | threshold=0.716，precision=0.732 |  |

**结论**：
1. **泛化成立**：「代码克隆检测要用代码向嵌入」不是 C/C++ 专属——Python 上 F2LLM 同样完美分离
   （负例最高 0.361 vs 正例最低 0.473，间隔 0.11）。上轮 §6.4 风险3 的结论从「C/C++ 一个数据点」升级为「C/C++ + Python 两个语言域一致」。
2. **top-1 锚暴露了 AP 看不见的差距**：bge-m3 的 AP 0.90 看着还行，但 top-1 只有 **63%**——30 条正例里 11 条
   把「同题改写」检索到**错误的登记文档**（如 p02238 的 3 条改写全部命中 p02239/p02255）。DLP 语义 EDM 场景下这意味着
   告警归因错误：报「疑似泄露文档 B」而真源是 A。F2LLM 30/30 全对。
3. **AP=1.000 的诚实解读**（三倍律）：n=50 全对时真实错误率 95% 上界≈3/50=0.060，即真实 AP/召回下界≈0.94——
   是「小样本内完美」，不可读作「证明完美」。样本放大是另一待测项（第 4 项），本轮未做。
4. **bge-m3 的失败模式跨语言一致**：与 C/C++ 轮相同——通用嵌入把「都是 Python 竞赛题风格」的表层相似压过了
   「算法语义等价」，负例整体抬到 0.63+，与正例无法用单一阈值切开（recall=1 时 precision 仅 0.732）。

## 口径与边界（诚实纪律）
- **卡型跨轮不同**：本轮 A10G（g5，g6/L4 无容量）；效果指标（AP/top-1/相似度）与卡型无关可跨轮对比，延迟类指标本轮未测。
- **英文 Python（本轮）vs 英文 C/C++（POJ-104）vs 中文业务机密（自建集）三层分开报，绝不平均**。
- **F2LLM 是通用多语言嵌入**（codefuse 代码团队出品、对代码友好，非 code-only），在两个代码域的碾压均为实测。
- **仍待测**：更大规模语料/评测集（第 4 项）、14B 量化、vLLM 并发拐点、结构化输出、整机 k6 分位。
