## 1. 前置条件

| 项 | 要求 |
|---|---|
| AWS 凭证 | `default` profile（全球区，us-west-2）；`sts get-caller-identity` 能过 |
| 本地工具 | `aws` (CLI v2)、`jq`、`base64` |
| DLP 主机 | `<TEST_INSTANCE_ID>`（`172.31.27.174`）已跑 `kiro-dlp-http` 判定服务（`:9000/health` 返回 ok） |
| 目录内文件 | `deploy.sh` / `config.env`（由 `config.env.example` 复制而来）/ `gen-ca.sh` / `kiro_addon.py` 齐备（`deploy.sh` 预检会强校验后两者存在） |

> ⚠️ **并发凭证冲突**：破坏性/批量 AWS 操作时，多个 Claude 会话共用同一 `default` 凭证会互相踩踏。
> 部署/拆除期间避免并发会话，排查用 CloudTrail `invokedBy` + 会话检索定位。

## 2. 配置 `config.env`

仓库里只有模板 `config.env.example`（真实资源 ID 不入仓，`config.env` 已 git-ignored）：

```bash
cp config.env.example config.env
# 编辑 config.env，填入你自己的 VPC / 子网 / DLP 主机 ID 与私网 IP
```

核心变量（完整清单见文件内注释；下面的 ID 均为占位示意）：

```bash
# —— 区域解耦（规格 D5，关键）——
export AWS_REGION="us-west-2"            # 资源落地区 = DLP 主机所在区（才能同 VPC 私网直达 172.31.27.174）
export KIRO_BACKEND_REGION="us-east-1"   # 仅用于拼 Kiro 域名；runtime.us-east-1.kiro.dev 与落地区无关
export PROJECT_NAME="kiro-dlp-mitm-v2"   # 资源前缀，避免与生产/旧节点撞名
#   ★ 若把域名也用 AWS_REGION 拼 → runtime.us-west-2.kiro.dev（不存在）→ 握手 hang

# —— 网络复用（不新建，与 DLP 同 VPC 同 AZ）——
export EXISTING_VPC_ID="vpc-xxxxxxxxxxxxxxxxx"      # 默认 VPC 172.31.0.0/16 (us-west-2)
export EXISTING_SUBNET_ID="subnet-xxxxxxxxxxxxxxxxx" # 公有子网, us-west-2a（与 DLP 同 AZ）

# —— EC2 —— 
export INSTANCE_TYPE="c6g.large"   # arm64 Graviton，us-west-2a 有货
export INSTANCE_ARCH="arm64"       # 必须与机型匹配
export EBS_SIZE_GB="20"
export KEY_NAME=""                 # 留空 = 仅 SSM 登录（推荐）

# —— 安全组 / 入站（锁死）——
export ADMIN_SSH_CIDR=""           # 空 = 不开 22（用 SSM）
export INGRESS_443_CIDR=""         # 空 = 不开公网 443（本机 loopback 自测 + SSM）
export ENABLE_PRIVATELINK="false"  # bump 上游走公网出口；无需 q/codewhisperer VPCE

# —— DLP 判定服务联动（方案二核心）——
export DLP_HOST_INSTANCE_ID="<TEST_INSTANCE_ID>"
export DLP_HOST_SG_ID="sg-xxxxxxxxxxxxxxxxx"        # deploy 会给它加 9000 入站（SG-to-SG）
export DLP_HOST_PRIVATE_IP="172.31.27.174"
export DLP_INSPECT_PORT="9000"
export DLP_INSPECT_URL="http://172.31.27.174:9000/inspect"
export DLP_FAIL_MODE="closed"      # 规格 D4：默认 fail-closed；灰度可临时 open（生产禁用）
export DLP_TIMEOUT="8.0"           # addon 判定调用总超时秒（按 Presidio p99 标定）
export DLP_MAX_BODY_BYTES="8388608" # 明文 body 上限 8 MiB，超限恒 fail-closed

# —— SNI 白名单（全部用 KIRO_BACKEND_REGION 拼）——
export SNI_DOMAINS=(
  "codewhisperer.${KIRO_BACKEND_REGION}.amazonaws.com"
  "q.${KIRO_BACKEND_REGION}.amazonaws.com"
  "cli.kiro.dev"
  "runtime.${KIRO_BACKEND_REGION}.kiro.dev"
  "management.${KIRO_BACKEND_REGION}.kiro.dev"
)

# —— 选择性 bump（唯一被解密的域名）——
export MITM_BUMP_DOMAIN="runtime.${KIRO_BACKEND_REGION}.kiro.dev"  # 必须是 SNI_DOMAINS 之一；置空 = 全透传（回滚开关）
export MITM_PORT="8443"            # nginx 把 bump 域 proxy_pass 到本机此端口；mitmproxy 在此 TLS 终结

# —— 企业 CA（EC2 现场生成，私钥不出机）——
export MITM_CA_DIR="/etc/mitm/certs"
export MITM_CA_ROOT_CN="Kiro-DLP-Verify Root CA"      # 客户端信任锚
export MITM_CA_INTER_CN="Kiro-DLP-Verify Issuing CA"  # Name Constraints 挂这里
export MITM_CA_PERMITTED_DNS="kiro.dev"               # 只能签 kiro.dev 及子域
export MITM_CA_ROOT_DAYS="3650"
export MITM_CA_INTER_DAYS="1825"
export MITM_MIN_MAJOR="11"         # mitmproxy ≥v11（修复请求走私 / mitmweb SSRF→RCE）
```

**回滚开关（记住）**：`MITM_BUMP_DOMAIN=""` → 退化为全透传，等价生产透传节点，不解密任何流量。

## 4. 八步编排详解（`deploy.sh` 做了什么）

| 步 | 动作 | 关键点 |
|---|---|---|
| **预检** | `aws`/`jq`/`base64` 存在、`sts` 能过、`gen-ca.sh`+`kiro_addon.py` 存在、`MITM_BUMP_DOMAIN` ∈ `SNI_DOMAINS` | 任一不过即 `die`；bump 域不在白名单 = 配置错误 |
| **1 网络** | 复用 `EXISTING_VPC_ID`+`EXISTING_SUBNET_ID`（校验子网属于该 VPC）；两者皆空才新建（`CREATED_NETWORK=true`）；只设一个 = die | 本轮走复用分支，`CREATED_NETWORK=false` |
| **2 proxy SG** | 建 `${PROJECT_NAME}-proxy-sg`；443 入站仅当 `INGRESS_443_CIDR` 非空、22 入站仅当 `ADMIN_SSH_CIDR` 非空；出站默认全放 | 本轮两者皆空 = 无公网入站，出站覆盖 443→kiro / 9000→DLP / DNS |
| **2.5 SG 联动**（D12） | 给 DLP 主机 SG 加一条「来自 proxy SG 的 9000 入站」（**按引用组，非 CIDR**）；**幂等**：已存在则不重复加、不纳入回滚（`DLP_SG_RULE_ADDED=false`） | 记录 `DLP_SG_RULE_ID`；**cleanup 必须先撤这条、再删 proxy SG**（否则 DependencyViolation） |
| **3 PrivateLink** | 仅当 `ENABLE_PRIVATELINK=true` 建 q/codewhisperer VPCE | 本轮 false，跳过（上游走公网出口） |
| **4 SSM IAM** | 建 `${PROJECT_NAME}-ec2-role`（+ `AmazonSSMManagedInstanceCore`）+ instance-profile；**幂等**：`get-role`/`get-instance-profile` 已存在则复用；profile 建后 `sleep 12` 等 IAM 传播 | `IAM_ROLE_CREATED`/`IAM_PROFILE_CREATED` 门控 cleanup |
| **5 user-data** | 生成 nginx `stream`（SNI map：bump→`127.0.0.1:8443` 字面、其余→`$name:443`、`default ""`）+ mitmproxy systemd 单元；`gzip -9`+base64 内嵌 `gen-ca.sh`+`kiro_addon.py`（**因 EC2 user-data 限 25600 字节**，原始 ~26.5KB 超限，压后 ~11KB） | 落地后 `base64 -d \| gunzip` 还原；`ENABLE_MITM=true` 当且仅当 bump 域非空 |
| **6 启 EC2** | Ubuntu 24.04（SSM 参数取 AMI，失败回退 describe-images owner 099720109477）；`IMDSv2 required`、gp3、绑 instance-profile；`KEY_NAME` 非空才加 `--key-name` | 等 `instance-running` |
| **7 EIP** | 分配 EIP + 关联实例 | 记录 `EIP_ALLOC_ID`/`EIP`；读 `PRIVATE_IP` |
| **8 输出** | 写 `client-hosts.txt`（EIP→各 SNI 域，**警告 EC2 本机绝不改 hosts 否则自环**）+ 打印拓扑/CA 分发指引/验证命令/日志尾/`cleanup.sh` | — |

### user-data 在 EC2 上的开机自举（关键动作）

1. `apt-get install nginx libnginx-mod-stream dnsutils openssl python3-venv python3-pip`。
2. 写 `/etc/nginx/nginx.conf`（stream + `resolver 169.254.169.253` + `sni.log`），`nginx -t` 后启。
3. 若 `ENABLE_MITM=true`：还原 `gen-ca.sh`+`kiro_addon.py`；`/opt/mitm-venv` 装 `mitmproxy>=11`（+httpx，
   失败非致命）；**版本断言**：mitmdump 主版本 < 11 → `FATAL exit 1`。
4. 建 system 用户 `mitm`（`--system --no-create-home --shell /usr/sbin/nologin`）。
5. 跑 `gen-ca.sh`（现场生成三级 CA，私钥留 `/etc/mitm/certs` 600）→ `chown -R mitm:mitm /etc/mitm`。
6. 写并启 `kiro-mitm.service`（`User=mitm` + 全套硬化 + `PYTHONUNBUFFERED=1` + 注入 `DLP_*`/`MITM_BUMP_DOMAIN` 环境）。

**部署后自检**（进 proxy 本机 SSM 会话）：

```bash
sudo systemctl is-active nginx kiro-mitm                 # 都应 active
sudo ss -ltnp | grep -E ':8443\b'                        # 期望 127.0.0.1:8443（绝不 0.0.0.0）
sudo journalctl -u kiro-mitm -n 30 --no-pager | grep -E '自检 OK|addon started|FAIL'
sudo tail -f /var/log/cloud-init-output.log              # 看 user-data 自举日志
```

## 5. CA 分发（真实客户端信任，本轮未做，留规程）

从 EC2 取出**根证书**（只取公开的 `root-ca-for-clients.crt`，私钥永不出机）：

```bash
# 经 SSM 从 proxy 本机读出根证书（示例：SSM 会话内 base64 出来再本地还原）
sudo cat /etc/mitm/certs/root-ca-for-clients.crt
```

Kiro 有多套 TLS 栈，**分别**信任（详见设计评估的双栈裁决）：

| TLS 栈 | 信任方式 |
|---|---|
| 系统 / Chromium | 导入系统钥匙串（macOS）/ `update-ca-certificates`（Linux）/ 企业 MDM 下发 |
| Node / Electron（IDE 推理腿在此） | `NODE_EXTRA_CA_CERTS=<root.crt>`；或 VSCode `http.systemCertificates:true` 走 OS 库 |
| Rust CLI | `SSL_CERT_FILE` / `AWS_CA_BUNDLE=<root.crt>` |
| Bun TUI | `NODE_USE_SYSTEM_CA=1` + root 装进系统库 + CLI ≥ 2.14.0 |

**铁律**：**绝不** `NODE_TLS_REJECT_UNAUTHORIZED=0` / `rejectUnauthorized:false` 绕过校验。

客户端 DNS override：把 `client-hosts.txt` 的映射（各 Kiro 域 → proxy EIP）写进**客户端**主机 hosts。
⚠️ **EC2 本机绝不改 hosts**，否则 mitmproxy 上游解析回自己成环。

### 彻底拆除

```bash
cd /Users/chenxqdu/cowork/kiro-dlp-content/方案二-selective-bump-mitm && ./cleanup.sh
```

`cleanup.sh`（`set -uo pipefail`，无 `-e`，单资源失败不中断）逐条打印将删资源，**必须输入 `yes` 才继续**，
然后**逆序**拆除：

1. **EIP**（先 disassociate 再 release）；
2. **EC2 实例**（terminate + `wait instance-terminated`，先彻底终止以消除引用）；
3. **SG 联动回滚**（⚠️ 顺序铁律：**先** 按 `DLP_SG_RULE_ID` 撤 DLP 主机 SG 上那条 9000 规则、**再**删
   proxy SG，否则 DependencyViolation）——**仅当 `DLP_SG_RULE_ADDED=true`**，他人预置则跳过、绝不误删；
4. **VPCE**（本轮无，PrivateLink=false）；
5. **安全组**（VPCE SG → proxy SG，带重试等引用释放）；
6. **IAM**（仅删本脚本创建的：`*_CREATED=true` 门控，先解绑再删 profile/role）；
7. **网络**（**仅当 `CREATED_NETWORK=true`**；本轮复用 = 保留不删）；
8. 删 `.deploy-state.env`。

**刻意不碰**：DLP 主机本体及其 SG 本身、其 22/4000 等现有规则；复用的 VPC/子网/路由/IGW；生产透传节点。
DLP 主机上停判定服务需另进 `<TEST_INSTANCE_ID>`：
`cd /home/ec2-user/kiro-dlp && docker compose -f docker-compose.dlp-http.yml down`。

## 7. L4 语义三态开关（DLP 主机侧配置）

L4 的开关**不在 addon 侧 `config.env`**，而在 **DLP 主机** `/home/ec2-user/kiro-dlp/docker-compose.dlp-http.yml`
的 `environment`（改后 `docker compose -f docker-compose.dlp-http.yml up -d` 重建即生效，bind-mount 无需重建镜像）。

| env | 作用 | committed 默认 |
|---|---|---|
| `DLP_L4_MODE` | 三态：`off`（不跑 L4）/ `async`（异步告警、不改 verdict）/ `sync`（可阻断） | **`async`** |
| `DLP_USE_BEDROCK_L4` | L4 后端：`true`=Bedrock（⚠内容出 VPC）/ `false`=离线启发式（不出 VPC） | **`true`** ⚠ |
| `DLP_L4_MODEL_KEY` | `main`=Qwen3-32B / `control`=Llama-3.1-8B | `main` |
| `DLP_L4_BLOCK_MIN_CONFIDENCE` | `sync` 模式合成 BLOCK 的置信阈值 | `0.7` |
| `DLP_L4_TIMEOUT_MS` | `sync` 墙钟上限 + 透传 boto `read_timeout`；超时降级放行 | `4000` |
| `DLP_L4_EXECUTOR_WORKERS` / `DLP_L4_QUEUE_MAX` | 后台线程池大小 / 背压上限（满则丢，不阻塞主链路） | `2` / `32` |
| `DLP_L4_SINK_PATH` | 可选：告警 JSONL 追加写此文件（默认仅 stdout，`docker logs kiro-dlp-http` 可捞） | 空 |
| `DLP_L4_SINK_RATIONALE` | 告警是否落 model `rationale[:200]`：`true`=落（与方案一一致，⚠ Bedrock 自由文本**可能回显输入片段**，知情接受风险）/ `false`=不落（sink 保证**零明文回显**，生产偏好） | **`true`** |

> ⚠ **committed 默认 `async`+Bedrock = 内容出 VPC**，是**知情的演示/标定 shipped default、非生产**。启动横幅会刺眼提示。
> 生产部署**必须** `DLP_USE_BEDROCK_L4=false` 并切自托管 VPC-local（GPU+vLLM）。

**`sync` 模式对 addon `DLP_TIMEOUT` 的预算要求**：`sync` 会在同步腿（L0–L3.5）之后再等 L4 至多 `DLP_L4_TIMEOUT_MS`。
addon 侧 `config.env` 的 `DLP_TIMEOUT`（默认 8s）须 **≥ L0–L3.5 实测预算 + `DLP_L4_TIMEOUT_MS`（默认 4s）**，
否则 addon 先超时 → 503 → fail-closed（安全但非预期的 BLOCK）。`async`/`off` 模式无此约束（同步腿立即返回）。

停判定服务：`cd /home/ec2-user/kiro-dlp && docker compose -f docker-compose.dlp-http.yml down`。
